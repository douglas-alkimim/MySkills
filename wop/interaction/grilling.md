# Decision-Focused Clarification

Clarification aligns decisions; it does not replace project inspection or user ownership.

Use it only when an unresolved choice can materially change the plan. Do not interview a fully specified request. Do not ask the user for facts discoverable from accessible files, schemas, or environments.

## Conversation protocol

1. Extract answered decisions first.
2. Build the dependency graph among unanswered decisions.
3. Ask from the current question frontier: questions whose prerequisites are settled.
4. Prefer one focused question per turn unless a small batch contains independent frontier questions.
5. Offer concrete alternatives and trade-offs when useful.
6. Accept defer, recommend, or unknown as valid answers.
7. Record the result as a decision, assumption, unknown, or discovery item.
8. Stop when no material decision remains unresolved.

The user owns scope. Surface contradictions and consequences rather than converting passive agreement into false certainty.

Some questions require experience, not conversation. When a choice depends on seeing behavior, create a bounded throwaway prototype or discovery item, specify what it must teach, and return the evidence to the decision.

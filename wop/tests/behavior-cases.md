# Skill Behavior Cases

Use these as forward tests against a fresh agent with the WOP skill. Evaluate the resulting decisions and artifacts, not exact wording.

1. Fully specified simple task: proceeds without an interview and produces a compact, valid package.
2. Ambiguous product task: asks a material user-decision question and does not invent scope.
3. Dependent decisions: asks only questions on the current frontier and does not ask a downstream question before its prerequisite is answered.
4. Existing project: inspects accessible evidence before planning or asking discoverable facts.
5. Complex software system: loads code plus applicable security, performance, and testing guidance and translates those concerns into work and evidence.
6. Scientific manuscript: loads document, editorial, LaTeX, and PDF guidance, then requires rendered inspection rather than source-only confidence.
7. Two disjoint outputs: demonstrates pairwise independence, exclusive ownership, wave-specific execution instructions, and permits same-wave execution without leaking that assignment into later prompts.
8. Two tasks editing one contract: identifies the interference and separates them into ordered waves or establishes genuine isolation; custom global, wave, and item context reaches exactly the intended prompts.
9. Empirical unknown: creates a bounded discovery or prototype item with evidence and a decision gate.
10. Existing-plan consultation: locates by stable ID or indexed metadata, returns the requested facts, and does not mutate files or SQLite.
11. Review without alteration: audits mechanics and semantics, reports findings with evidence, and creates no revision or lifecycle event.
12. Content update: preserves ID/created_at, increments version exactly once, updates updated_at, regenerates prompts, renames, updates history/index, and validates.
13. Plan comparison: keeps identities separate and compares scope, requirements, contracts, dependencies, evidence, and status without silently merging.
14. Consolidation: resolves contradictions explicitly, creates or deliberately selects an identity, preserves source traceability, and does not delete sources.
15. Archive and restore: preserves the complete package, operational states, identity, history, relations, prompts, and editorial timestamp.
16. Delete: resolves the exact target, inspects dependents, explains consequences, requires immediate confirmation, stages recovery, and retains a tombstone.
17. Universal multilingual plan: selects explicit language over conversation language and English only when unclear; works without code changes in pt-BR, en, es, fr, de, ja, zh-CN, ar, and an unregistered valid tag; keeps README and all generated instructions in the selected language; preserves technical literals; validates arbitrary translated headings through structural markers; and replaces every prompt plus SQLite metadata after a language change.
18. Multidisciplinary plan: loads only the relevant code and document modules, models cross-domain handoffs explicitly, and prevents parallel work from sharing mutable artifacts.
19. Minimal Compact plan: keeps a bounded low-risk request as one wave and one item, omits irrelevant empty sections, generates both required prompts, and passes essential validation.
20. Adaptive depth: applies Compact, Standard, and Extensive to the same base outcome under progressively higher risk, dependency, external-effect, and coordination contexts; preserves universal invariants while increasing audit evidence proportionally.
21. Selective reference loading: DISCOVER and READ load only workspace/discovery procedures, CREATE loads Core and agent writing plus only applicable modules, and Decision-Focused Clarification is loaded only for unresolved user-owned decisions.
22. Localized example routing: finds pt-BR and Spanish plans under `examples/localized-plans/`, preserves their structural markers, validates them, and never treats their languages as a closed support catalog.
23. Anti-fragmentation: keeps cohesive work together, rejects a multi-item wave without independence and ownership evidence, separates a genuine prerequisite or write conflict, and introduces parallel items only when execution is meaningfully independent.

For every case, record the routing files used, the material decisions made, the produced package fields, the validation result, and the evidence supporting the expected behavior. A response that merely repeats phase names without applying dependency, ownership, gate, evidence, or governance rules fails.

Failure conditions include unnecessary interview, false inspection claims, artificial task fragmentation, Compact boilerplate with irrelevant empty sections, same-wave dependency, partial wave release, a global protocol that assigns particular items, foreign assigned-item markers, authorization of later waves, lost custom context, invalid custom selectors, duplicated prerequisite blocks, stale prompt hash, acceptance without evidence, silent mutation during review, unnecessary Core or specialist loading for read-only operations, unconfirmed deletion, lost archive state, unreported recovery residue, a closed locale catalog, English fallback when the language is known, untranslated generated prose, obsolete-language prompt residue, and mixed plan language outside legitimate technical literals.

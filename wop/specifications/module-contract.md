# Specialist Module Contract

Every WOP specialist module must define:

1. Activation: requests and artifacts that require it.
2. Exclusions: similar work it must not attract.
3. Inputs: domain facts, constraints, and access needed.
4. Decision rules: non-obvious priorities and trade-offs.
5. Risks: domain-specific failure modes.
6. Plan additions: required fields, contracts, or work items.
7. Verification: appropriate procedures and evidence.
8. Acceptance: conditions beyond core WOP criteria.
9. Routing: optional submodules and when to load them.

The module inherits core/principles.md, uses the common wave and item schema, and preserves user authorization boundaries. It must not redefine universal statuses, weaken predecessor gates, duplicate generic planning prose, or require unsupported tools.

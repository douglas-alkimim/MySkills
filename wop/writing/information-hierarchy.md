# Information Hierarchy

Use three layers:

1. SKILL.md routes operations and modules and carries universal invariants.
2. Core, lifecycle, specialist, and specification files contain conditional method detail.
3. Each generated plan and prompt contains all execution-critical information for that project and wave.

Within Standard and Extensive plans, order information from outcome and context through requirements, contracts, waves, traceability, verification, acceptance, protocol, and history. Compact may collapse irrelevant intermediate layers and use direct requirement-to-item verification while preserving the same execution guarantees. Within a prompt, place technical authorization first, then the global protocol, current-wave execution scope, predecessor verification, scoped shared context, and the completion contract. Give each fact one primary location instead of repeating prerequisites or the complete wave.

Do not force an executor to chase references for a frozen contract or acceptance condition. External project artifacts may remain external, but summarize their relevant contract and identify the exact path or interface.
